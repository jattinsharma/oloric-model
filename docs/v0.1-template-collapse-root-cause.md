# Oloric v0.1 — Template Collapse Root-Cause Audit (Training Data & Target Construction)

**Date**: September 26, 2026
**Subject**: Root cause of the v0.1 template collapse observed in the final semantic evaluation (`evaluation/oloric-v0.1/semantic_report.md`): 19/19 schema-valid responses emitted unfilled placeholders (`[clear, concise definition]`, `[concrete example]`, `1) [question 1]?`, `[hint 1]`).
**Scope**: read-only audit of the authoritative dataset (`data/generated/enhanced_seed_data.jsonl`, 480 examples), its 384/48/48 splits, the 20-example held-out benchmark, the dataset generator, and the training/inference pipeline code.
**Files modified by this audit**: none (this document only).

---

## 1. Method

Programmatic recursive scan of **every string field** of every record (instruction, context and all its subfields including document_context and conversation turns, target and all its subfields: response, understanding_check, diagnosis, memory, strategy, difficulty, action) against:

- square-bracket slots: `\[[^\]\[]{2,60}\]`
- angle-bracket slots: `<…>`, curly-brace slots: `{…}`
- the literal phrases listed in the task: `clear, concise definition`, `concrete example`, `specific evidence`, `question 1`, `question 2`, `Key evidence`, `key point about/to remember`
- instructional language: `placeholder`, `TODO/TBD/FIXME/LOREM`, `fill in / left blank / insert here`

All counts below are exact, reproducible from this method. False-positive handling: `[H⁺]` (hydrogen-ion chemistry notation in `retrieved_evidence`) matches the bracket regex but is not a placeholder and is excluded from placeholder counts where stated.

## 2. Answers to the eight audit questions

**Q1. How many training examples contain literal placeholders?**
**458 / 480 (95.4%)** contain at least one placeholder in some field. The 22 fully clean records are 22 of the 24 `diagnostic_questions` examples (the other 2 contain only the `[H⁺]` chemistry false positive).

**Q2. How many target responses contain placeholders?**
**456 / 480 targets (95.0%)** contain at least one placeholder inside `target`. Breakdown of placeholder occurrences by target subfield:

| Target subfield | Placeholder occurrences |
|---|---|
| `target.response` | **1,300** |
| `target.understanding_check.expected_answer` | 672 |
| `target.memory.content` | 541 |
| `target.understanding_check.question` | 48 |
| `target.memory.title` | 24 |
| **Total in targets** | **2,585** |

Note the asymmetry: `understanding_check.question` is mostly filled (only 48 placeholder hits) while `expected_answer` is mostly placeholder (672) — the generator wrote real check questions but templated their answers.

**Q3. What percentage of the 480 training targets contain them?**
**95.0%** (456/480; the 24 clean targets are exactly the `diagnostic_questions` category).

**Q4. Are placeholders concentrated in particular categories?**
They are **uniform across 19 of 20 categories** — every one of these has 24/24 placeholder-bearing `target.response` values: analogy, concrete_example, context_retention, document_grounded, error_correction, follow_up_questions, hint_based_teaching, memory_generation, misconception_detection, multi_turn_tutoring, numerical_example, partial_understanding, practice_questions, prerequisite_detection, repeated_confusion, simple_explanation, simplification, strategy_switching, understanding_confirmation.
**The single exception is `diagnostic_questions`: 0/24** — its targets were fully materialized (real questions and real expected answers). This exception is diagnostic gold (see §6).

**Q5. Are placeholders present in validation/test examples?**
Yes, at the same rate — the splits are a clean partition of the seed (`train ∪ val ∪ test` = seed IDs, disjoint, 384+48+48=480):

| Split | Records w/ placeholders (any field) | Targets w/ placeholders |
|---|---|---|
| train | 366/384 (95.3%) | 366/384 |
| validation | 46/48 (95.8%) | 45/48 |
| test | 46/48 (95.8%) | 45/48 |

Every split the model was trained, validated, and "tested" on teaches the placeholder pattern; the test split never measured the ability the benchmark measures.

**Q6. Are the placeholders present in the 20 held-out benchmark?**
**No.** The benchmark contains zero placeholder slots. The only regex hits are 2 × `[H⁺]` in `retrieved_evidence` (chemistry notation; false positives). Benchmark `target` fields are fully materialized — they are the same template *shells* as the training targets but with content substituted in (sometimes factually wrong content, e.g. the BMI formula passed off as a "Food Preservation" hint — flagged previously in the semantic evaluation). So the benchmark shares the templates' scaffolding while containing no unfilled slots; training never demonstrated what goes in the slots, and the benchmark assumed it.

**Q7. Are the placeholders escaped or represented as literal text?**
**Literal text.** The raw file contains **0** escape sequences (`\[`); the literal string `[reason]` appears **205 times** in raw text. In JSON, values like `"refers to [detailed explanation]"` are plain characters. Nothing in the pipeline escapes, masks, or interprets them; they are ordinary supervised tokens.

**Q8. Are they generated by the dataset generator or by a formatting/template layer?**
By the **dataset generator**. `scripts/generate_seed_data.py` contains dozens of f-strings that write the placeholders directly into targets, e.g.:

- L157 (simple_explanation): `f"{concept} in {domain} refers to [detailed explanation]. It is important because [reason]. For example, [concrete example]."`
- L459 (follow_up_questions): `f"...Consider these questions: 1) [question 1]? 2) [question 2]? 3) [question 3]?"`
- L669 (hint_based_teaching): `f"...Hint 1: [hint 1]. Hint 2: [hint 2]. Hint 3: [hint 3]. See if you can put these together to understand {concept}."`
- L867: `f"{concept} in {domain} is defined as [clear, concise definition]. It's important because [reason]. A key example is [example]."`

Critically, a **fixed generator exists in the same repo** — `scripts/generate_seed_data_improved.py` — which fills the same slots with real content via helpers (`get_concept_explanation(domain, concept)`, `get_concept_example(domain, concept)`, real prerequisites and examples; see its L797/L812 for the hint template fully materialized). However, it writes to `improved_seed_data.jsonl`, **which does not exist** in `data/generated/` (contents: `enhanced_seed_data.jsonl`, its `.backup`, `seed_data.jsonl`, `audit_stats.json`, `dataset_metadata.json`). The training dataset was produced by the unfixed generator; the improved generator was never run (or its output was never adopted).

## 6. Probable root cause

The supervised targets — the exact strings the adapter was trained to reproduce — **are themselves unfilled templates**. Across 384 training examples, the model was repeatedly optimized to emit, verbatim, strings like `X is defined as [clear, concise definition]. It's important because [reason]. A key example is [example].` QLoRA faithfully learned precisely that mapping: given the benchmark's prompt shape, it reproduces the template shell with the slots left literal. The three named template families observed at inference map one-to-one onto generator templates (definition L867/L157; misconception-correction L436-family; document-quoter L908-family).

Two observations corroborate "the model learned exactly what it was shown":

1. **The one clean category transferred correctly.** `diagnostic_questions` targets are fully materialized, and on the benchmark's four diagnostic_questions items the model emits diagnostic-style output (misconception-correction template with a real misconception string) — imperfect, but the only family where it produces any real, slot-free content beyond scaffolding.
2. **Context templates taught context-shaped boilerplate.** Tutor turns in multi-turn contexts contain `[different concept]`, `[first explanation]` etc., which explains the doc-quoter template's insistence on naming "the selected text / surrounding context / retrieved evidence" without ever quoting them.

Why QC missed it: `scripts/validate_dataset.py`, `scripts/validate_seed_data.py`, and `scripts/quality_review.py` validate JSON structure, schema compatibility, and display truncated samples (first ~200 chars — which often *end before* the slots) — none checks for placeholder tokens in content. The audit metadata ("strong Oloric trajectory" counts, etc.) is structural only.

## 7. Alternative explanations considered and ruled down

- **Inference-side template injection (E)**: ruled out — no slot strings exist anywhere in the inference/formatting code paths; also the placeholders vary per-item exactly as the training templates would (and item 18, the schema-invalid one, produced fully filled content, showing the model is capable of filling slots when it deviates from the learned shell).
- **Tokenizer artifacts (D)**: ruled out — literal text, no escaping, identical bytes in dataset and output.
- **Insufficient training / underfitting alone**: insufficient as an explanation — 3 epochs on 384 examples reproduced the *exact* target strings, which is over-consistent memorization of templated targets, not generic underfitting. Underfitting would not deterministically reproduce bracket slots.
- **Benchmark contamination producing the collapse**: the benchmark targets are template-filled; a model overfit to shells would still need the shell vocabulary from training — the causal direction is training → inference, not benchmark → inference. The earlier contamination caveat (benchmark targets resembling training data) stands as a separate measurement-validity concern.
- **Formatting-layer bug (B/C)**: cleared by code inspection (§4).

## 8. Recommended corrective action (not performed)

1. **Regenerate the dataset with content-filled targets.** Run (or extend) `generate_seed_data_improved.py` — it already contains the slot-filling helpers — so every target string is fully materialized, then re-run `validate_dataset.py` + a new placeholder gate.
2. **Add a placeholder gate to validation** (machine-checkable): fail validation if any target/context string matches `\[[^\]]{2,60}\]` (with an allowlist for genuine notation like `[H⁺]`), or `\bplaceholder\b`. Add the same check to `quality_review.py`.
3. **Fill templates with concept-grounded, fact-checked content** (use the existing per-domain helper content; have a factual review pass — the current benchmark targets show the fill-in path can introduce factual errors, e.g. the BMI-as-Food-Preservation hint).
4. **Re-split and re-verify**: confirm 0 placeholder tokens in train/validation/test before retraining.
5. **Only then retrain** (explicitly out of scope for this audit), and re-run the same 20-example benchmark + rubric evaluation for a true before/after.
6. Optionally: add a post-hoc inference guard that flags any generated string containing bracket-slot patterns, so this failure class can never silently pass structural schema validation again — as it did here: **19/20 schema-valid outputs were content-invalid.**

## 9. Bottom line

The template collapse is a **training-data defect (origin A)**: 95.0% of the supervised targets in the authoritative 480-example dataset are unfilled template shells authored by `scripts/generate_seed_data.py`'s f-strings, while a fixed generator (`generate_seed_data_improved.py`) existed but was never used to produce the training file. Formatting, training, and inference layers are cleared. The model did not fail to learn — it learned exactly what it was taught.
