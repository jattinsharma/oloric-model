# Oloric v0.2 Dataset — Content-Quality Sanity Report

Phase 4 of the v0.2 repair cycle. Read-only audit of `data/generated/oloric_v02_dataset.jsonl`
(480 records, sha256 `0b6115c5f8ce5c39e6ee1e79654b69c1a6155ab625c985aba154d3e925cffd1a`).
Nothing in the dataset, v0.1, the benchmark, or any config was modified during this phase.

Scope of the known caveats being audited: the dataset is **compact** (480 records, 20 categories × 24),
**generator-grade** (deterministic templates over fixed helper pools), and uses **fixed example pools**
shared with the benchmark's lineage. This report measures how much those caveats actually hurt
training quality.

## 2. The 144 warnings — full classification

warnings. Note: `hint 3` appears 24× and `specific evidence` 24×; `hint 1`/`hint 2` 48× each

### 2.5 By domain
Perfectly uniform: 24 per domain × 6 domains (accountancy, economics, general_academic,
mathematics, nutrition_food_science, science). No domain is disproportionately affected.

### 2.6 Are any of them real training-quality problems?

**No.** Each is load-bearing rather than contamination:
- `hint N` strings are the actual hint-scaffolding content of hint_based_teaching
  (e.g. `v02_mathematics_hint_based_teaching_002`: "Hint 1: equalities like sin²θ + cos²θ = 1…").
  Removing them would destroy the pedagogy the category exists to teach.
- `specific evidence` is the task instruction itself for document_grounded
  (e.g. `v02_science_document_grounded_003`: "Teach Plate Tectonics using specific evidence from the
  document"). Responses are genuinely grounded in `document_context.selected_text`.

The literal-phrase heuristic is doing its job: it flags *candidates* for review; review confirms they
are intentional. **0 of 144 warnings represent an actual training-quality problem.**

## 3. Quantitative content checks (script-verified)

### 3.1 Template repetition
Distinct `target.response` per category: 19–24 distinct out of 24 (max repeat 2–3). Only two
sentences are reused ≥6×:
- "I notice there's a misunderstanding in your work." ×24 (error_correction opener — a
  genre-appropriate formulaic opener, mirrors real tutor phrasing)
- "2) Do you remember the definition, an example, or neither?" ×6 (diagnostic_questions variant 2)

Verdict: repetition is visible but **not collapse-level** (compare v0.1: unfilled `[...]` skeletons
with 2,585 placeholders in targets).

### 3.2 Understanding checks (UC)
456 UCs total. **96 (21%) are recall-only**: ≥40 chars of the UC `expected_answer` appear verbatim
in the response, so the model can pass by echoing the explanation. The other 354 ask for
application/transfer ("Based on the examples provided…", "How would you explain X to someone
else…"). **Actionable weakness, not a blocker.**

### 3.3 Memory candidates
211 `memory.candidate=true`. **0** have their content's first 60 chars verbatim inside
`target.response` (no pure echo-of-target). However, memory content largely paraphrases the same
explanation/reason strings used in the response — shallow but structurally correct.

### 3.4 Benchmark leakage (the critical check)
- **0** exact `target.response` matches vs the 20 held-out benchmark items.
- **0** benchmark IDs present in v0.2 IDs.
- Near-duplicate target pairs (Jaccard ≥ 0.65): **14 pairs, max 0.764**, e.g.
  `v02_economics_numerical_example_004` ↔ `economics_numerical_example_029` (0.764),
  `v02_nutrition_food_science_follow_up_questions_002` ↔ `…_035` (0.731),
  `v02_general_academic_concrete_example_004` ↔ `…_040` (0.724).
  Root cause: the benchmark targets were built from the **same fixed example pools** in
  `generate_seed_data_improved.py` (shared lineage; v0.1 has the same heritage). These are
  different records with different concepts/difficulty — family resemblance, not copies.
- 16 instructions are Jaccard-identical to benchmark instructions (generic task phrasing,
  input-side only; disclosed in the Phase 3 audit).
- **Verdict: no benchmark target duplication, no benchmark-specific answer leakage, no benchmark
  examples copied into training.**

## 4. Sample review

Coverage: **100 records sampled (5 × 20 categories)**, every domain hit 14–18×; plus all 48
depth-4/5 multi-turn records inspected. For each sampled record, instruction, context,
conversation history, target response, diagnosis, understanding check, memory, and
strategy/action alignment were inspected.

### 4.1 Strategy/action alignment
All 480 records use `action=explain` with the mode carried by `strategy`
(simple_explanation / analogy / hint / practice / misconception_correction / prerequisite /
diagnostic_questions / …) — one consistent (action, strategy) pair per category. This matches the
v0.1 benchmark targets' own convention (target.action=explain + strategy=<mode>), so it is
**consistent with the existing data lineage and accepted as-is**, not a new defect. Note this
convention for future generator changes: reviewers may eventually want action to vary by mode.

### 4.2 Representative strong examples
- `v02_science_prerequisite_detection_004` (Natural Selection): clean gap narrative, correct
  `diagnosis.missing_prerequisite`, memory candidate correctly shaped ("You must understand
  measurement units before learning Natural Selection.")
- `v02_mathematics_repeated_confusion_003` (Matrix Operations, depth 5): multi-turn escalation
  (still confused → new approach → still confused), coherent pivot ("computer graphics, statistics,
  and engineering all reduce to matrix computations"), UC asks for the breakthrough, memory
  candidate is a recovery strategy, not an echo.
- `v02_science_document_grounded_003` (Plate Tectonics): genuine document grounding — quotes
  `selected_text`, cites surrounding context, memory anchored "From our reading: …"
- `v02_accountancy_concrete_example_001` (Double-Entry Bookkeeping): example actually matches the
  concept (assets/liabilities/equity identity).
- `v02_economics_context_retention_001` (Monetary Policy → Supply and Demand): prior concept
  correctly recalled and connected.

### 4.3 Representative weak examples (exact IDs)
All defects trace to the upstream improved generator's fixed pools, not to the v0.2 builder.

1. **Concept-string typos → topic/answer mismatch (the worst defect).** Upstream
   `DOMAIN_CONTENT` contains `" Vitamin Absorption"` with a leading space, so the per-concept
   explanation table missed it and 5 records use the BMI fallback — a formula for BMI, not
   vitamins:
   - `v02_nutrition_food_science_partial_understanding_002`
   - `v02_nutrition_food_science_context_retention_003`
   - `v02_nutrition_food_science_analogy_002`
   - `v02_nutrition_food_science_follow_up_questions_002`
   - `v02_nutrition_food_science_memory_generation_001`
   Plus 2 same-fallback records from other patched-table misses:
   - `v02_nutrition_food_science_context_retention_004` (Metabolism)
   - `v02_nutrition_food_science_context_retention_002` (Enzyme Activity)
   Total 7 records (1.5% of dataset) contain the literal fallback `defined for this course by`.
   6 records carry messy concept strings (`" Vitamin Absorption"` ×5, plus one more
   `practice_questions_004` where the typo exists but the response happens to be fine).

2. **Misconception drawn from the domain pool, unrelated to the concept.**
   - `v02_science_misconception_detection_004`: concept Chemical Bonding, misconception
     "Electric current flows from positive to negative".
   - `v02_general_academic_misconception_detection_002`: concept Effective Communication,
     misconception "Published research is always correct".
   The correction text then "refutes" the misconception using the concept definition, producing
   non-sequiturs. Systematic across all 24 misconception_detection records to varying degrees.

3. **Analogy splice grammar.** "X is like Y is like Z. Just as Y is like Z, X …"
   - `v02_nutrition_food_science_analogy_001/002`: "Vitamin Absorption is like Enzymes are like
     specialized tools".
   - `v02_mathematics_analogy_002`: "Trigonometric Identities is like A function is like a
     machine."
   Systematic across the analogy family (analogy, strategy_switching) — the analogy pool strings
   are themselves full "A is like B" sentences spliced into an "is like" frame.

4. **Strategy_switching fragments don't cohere.** `v02_economics_strategy_switching_002`:
   "Think of Supply and Demand like a process. Just as a tool helps us accomplish tasks…" —
   the frame noun ("process") and the analogy vehicle ("tool") are independently drawn and often
   mismatched; the closing assertion is generic.

5. **Unrelated contrast formula in simplification.** `v02_science_simplification_002`:
   "Natural Selection … instead of the technical definition involving pH = -log[H⁺]" — the
   "technical definition" contrast is randomly drawn from the domain formula pool and contradicts
   the concept.

6. **Fixed example pools crossing concepts.**
   - `v02_mathematics_memory_generation_003` / `v02_mathematics_multi_turn_tutoring_003`:
     "A key example is If a fair coin is flipped 100 times…" attached to Quadratic Equations.
   - `v02_mathematics_numerical_example_002`: quadratic solve presented as the numerical example
     for Exponential Functions.
   - `v02_science_numerical_example_002`: chemistry stoichiometry example for DNA Replication.
   - `v02_accountancy_concrete_example_003`: assets/liabilities example for Budget Variance
     Analysis.

7. **Glue-text awkwardness in multi_turn_tutoring.** The *reason* string (a full clause) is
   spliced into a noun slot: "how does it helps understand how economies function and make
   informed decisions work in practice" (`v02_economics_multi_turn_tutoring_003`). Systematic
   across the 24 multi_turn_tutoring records and some context_retention UC answers
   ("both are important for it explains natural phenomena…").

8. **Superficial prerequisite detection.** `v02_economics_prerequisite_detection_002`:
   "graph interpretation is essential because it helps understand how economies function…" — the
   prerequisite is real and `missing_prerequisite` is correctly set, but the justification is the
   generic domain reason rather than a prerequisite-specific one. Structurally correct,
   semantically thin. (Same pattern in `v02_science_prerequisite_detection_003/004`.)

9. **Hint 1 gives away the definition.** `v02_mathematics_hint_based_teaching_002`: "Hint 1:
   equalities like sin²θ + cos²θ = 1 that hold for all angle values" — the first hint is the full
   definition, so the scaffolded-reveal shape is pedagogically inverted.

10. **Memory candidate truncation.** `v02_general_academic_understanding_confirmation_002`:
    "You now understand Research Methods well enough to If a researcher has data from…" — the
    competence sentence is spliced into an "enough to <verb>" slot. Cosmetic.

Counts for the headline defects: **7** fallback/topic-mismatch records, **96** recall-only UCs,
**2** analogy-splice records detected by exact string (family-wide pattern), **2**
"coin-flip-for-quadratics" cross-concept examples, **1** truncated memory, plus the systematic
misconception-mismatch and reason-as-noun patterns.

## 5. Categories requiring repair (ranked)

| Priority | Category / family | Defect | Suggested fix (future v0.3, not this phase) |
|---|---|---|---|
| 1 | nutrition_food_science concept strings | `" Vitamin Absorption"` leading-space typo → BMI fallback topic mismatch in 7 records | Fix upstream `DOMAIN_CONTENT` keys; add per-concept entries for Metabolism, Enzyme Activity; strip concept strings at build time |
| 2 | understanding_confirmation (+ follow_up_questions UCs) | 96/456 UCs recall-only (verbatim-copy) | Generate UCs requiring transfer/application; forbid expected_answer substring of response |
| 3 | analogy / strategy_switching | "is like X is like Y" splice; incoherent frame/vehicle pairs | Store analogy vehicle as (frame, vehicle) pair; generate single coherent sentence |
| 4 | misconception_detection / error_correction | Domain-pool misconceptions unrelated to concept | Concept-specific misconception lists (or filter pool by concept tags) |
| 5 | multi_turn_tutoring / context_retention | Reason-clause spliced into noun slot | Rephrase templates to use reasons as clauses ("because …") |
| 6 | memory_generation (+ memory candidates generally) | Content paraphrases the same explanation string; occasional truncation/splice | Diversify memory phrasing; validate candidate sentences end with terminal punctuation |
| 7 | prerequisite_detection | Generic justification for the prerequisite | Prerequisite-specific reason table |
| 8 | simplification | Unrelated "technical definition" contrast | Contrast strings must come from the concept's own domain formula |
| 9 | numerical_example / concrete_example | Fixed example pools cross concepts within a domain | Concept-tagged example pools |

## 6. Overall dataset-quality risks

- **Low risk:** placeholder contamination (0), benchmark leakage (0 exact, ≤0.764 Jaccard family
  resemblance with shared-pool lineage), schema validity (0 errors), ID integrity (0 dups),
  split hygiene (384/48/48, seed 42, disjoint).
- **Medium risk:** ~1.5% of records have factually mismatched content (the 7 fallback records);
  21% of UCs are trivially passable by echo; multi_turn "how does it [clause] work in practice"
  teaches slightly broken English if overfit.
- **Accepted-by-design (disclosed):** compactness (480 records), generator-grade templated
  phrasing with fixed example pools, `action=explain` convention, 16 input-side instruction
  matches vs benchmark.

The compact, generator-grade character means the model will learn the *shape* of tutoring
behavior (turn structure, strategy labels, memory/UC/diagnosis fields) reliably; fine-grained
semantic quality of explanations is capped by the pool quality. Fine-tuning on this data will not
reproduce the v0.1 collapse (no unfilled slots anywhere), but explanation polish will remain
generator-grade until the §5 fixes land in a v0.3.

## 7. Verdict

- Placeholder gate: PASS (0 placeholders). Schema: PASS (0 errors).
