## 3. Files Changed (and why each change was necessary)

### 3.1 `scripts/train_qlora.py` — encoding fix (bug fix, necessary)
`load_dataset()` opened JSONL without `encoding='utf-8'`. On Windows the default codec is cp1252 and the v0.2 dataset's Unicode content (e.g. `²` in BMI formulas) raises `UnicodeDecodeError`. **Preflight caught this on first run.** Lightning/Linux would default to UTF-8, but the file must work identically in both environments. `src/oloric/data.py` already opened UTF-8; `train_qlora.py` was the only outlier. One-line change: `open(file_path, 'r')` → `open(file_path, 'r', encoding='utf-8')`.

### 3.2 `scripts/train_qlora.py` — three optional CLI overrides (smoke enablement, minimal)
v0.1 had no way to redirect HF `Trainer` intermediate checkpoints (they follow `training.output_dir` = `./checkpoints` from model.yaml) or to correct the scheduler step math for a 12-example run. Added flags, all defaulting to `None` (v0.1 behavior byte-identical when unused):

- `--trainer-output-dir` → `training_config["output_dir"]` (intermediate ckpts isolated under `checkpoints/oloric-v0.2-smoke/trainer_intermediate/`)
- `--num-train-epochs` → `training_config["num_train_epochs"]` (1 for smoke)
- `--dataset-size` → `training_config["dataset_size"]` (12; drives `steps_per_epoch`/`total_steps`/`warmup_steps` in `validate_training_parameters`)

**Deliberately not done:** no YAML files modified, no new smoke YAML. `configs/model.yaml`, `configs/qlora.yaml`, `configs/dataset.yaml` are untouched — QLoRA identity (§1 item 7) is inherited verbatim from v0.1, which is exactly what "same config" requires.

### 3.3 `scripts/preflight_smoke_v02.py` — NEW (CPU preflight harness)
11 checks: v0.2 loads (real loader + real schema), real-tokenizer tokenization, label-mask geometry, collator batch, Trainer batch assembly, smoke param resolution through the real `validate_training_parameters` chain + QLoRA-identity assertions vs v0.1, checkpoint dirs, reload layout requirements, and a subprocess probe of the exact smoke command that runs to the GPU boundary and stops there deterministically (`HF_HUB_OFFLINE=1` + nonexistent `--model-name`).

### 3.4 `scripts/scan_smoke_output.py` — NEW (post-smoke output gate)
Placeholder scanner for generated output (the eventual "no placeholder strings" check): scans raw text or JSONL (covers `evaluate.py` `responses.jsonl` `raw_response`/`raw_generated_text` fields), reusing `validate_dataset_content.py` patterns. Adds one tight extension: multi-element ion notation (`[HCO3⁻]`, `[CH3COO⁻]`) allowlisted — single-element ions were already covered; word-like slots (`[reason]`, `[explanation]`, `[hint 1]`) still fail. Regression-tested both directions.

### Untouched (guardrails)
`data/generated/oloric_v02_dataset.jsonl`, `data/splits_v02/*`, `data/generated/enhanced_seed_data.jsonl`, `evaluation/benchmark.jsonl`, all configs/*.yaml, all `src/oloric/*` modules, all v0.1 artifacts and checkpoints. Guardrail hashes verified unchanged (§6).

## 4. Exact Lightning AI Command

Run from the repo root on the Lightning Studio (1× L4 24GB), after `git pull`:

```bash
python scripts/train_qlora.py \
  --train-file data/splits_v02/train.jsonl \
  --val-file data/splits_v02/validation.jsonl \
  --output-dir ./checkpoints/oloric-v0.2-smoke \
  --trainer-output-dir ./checkpoints/oloric-v0.2-smoke/trainer_intermediate \
  --max-train-samples 12 \
  --max-val-samples 2 \
  --num-train-epochs 1 \
  --dataset-size 12 \
  --logging-steps 1 \
  --save-steps 50
```

Command pattern mirrors the frozen v0.1 manifest command (`docs/oloric-v0.1-training-manifest.md` §7) with smoke-specific flags appended. Every flag is resolved by the real CLI parser and the full `validate_training_parameters` chain (verified end-to-end by preflight check 8).

**Smoke run math (resolved by validator):** 12 examples ÷ (1 × 4 grad-accum) = 3 steps/epoch × 1 epoch = **3 optimizer steps**; warmup = 1 step; `logging_steps=1` → 3 log lines with loss values (finite check); `save_steps=50` → no intermediate ckpt during the run, final adapter saved to `final_model/`.

## 7. Remaining Risks

1. **bitsandbytes on CPU** — 4-bit NF4/double-quant is CUDA-only. Local preflight covers everything except actual model weight loading; the model-load + QLoRA path is the one component only verifiable on Lightning. Mitigation: identical stack (transformers 5.17.0, peft 0.21.0, bitsandbytes 0.50.2, torch 2.8.0+cu128) already completed the v0.1 L4 run.
2. **12/384 sample slice** — `--max-train-samples 12` takes the first 12 lines of train.jsonl (10 distinct categories by construction of the split; deterministic, seed-42 ordering). Not category-balanced by design — smoke tests mechanics, not learning.
3. **`--dataset-size 12` must stay in sync** — if the sample count is changed, `--dataset-size` must change with it, or warmup/total-steps math will be wrong (cosine schedule shape, not correctness of masking).
4. **Placeholder collapse of a fresh adapter** — 3 steps on 12 examples cannot teach the model to avoid template output; the post-run placeholder scan is a *mechanics* check (pipeline integrity), not a *quality* check. Quality evidence comes only from the full v0.2 training run.
5. **Windows `data/` whitelist scope** — `data/splits_v02/` is currently tracked via explicit paths added in commit `6d44897`; if new files are ever added under it, a `.gitignore` whitelist line (`!data/splits_v02/*.jsonl`) would be needed. No action this phase.
6. **Known v0.2 content caveats** (from Phase 4, informational): 7 BMI-fallback topic-mismatch records and fixed example pools remain in the audited dataset — deferred to the v0.3 repair table; they do not block the smoke run.
