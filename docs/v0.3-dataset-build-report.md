# OLORIC v0.3 Dataset Build Report

## Overview
This report documents the generation of the `oloric_v03` dataset, which completely replaces the flawed v0.2 data generation pipeline while strictly adhering to the 480-record schema (24 records across 20 categories).

**Dataset Paths:**
- Full dataset: `data/generated/oloric_v03_dataset.jsonl` (480 records)
- Train split: `data/splits_v03/train.jsonl` (384 records)
- Validation split: `data/splits_v03/validation.jsonl` (48 records)
- Test split: `data/splits_v03/test.jsonl` (48 records)

## Root-Cause Mitigations Implemented

The v0.3 build explicitly addresses the four major behavioral failures identified in the v0.2 audit (`docs/v0.3-root-cause-audit.md`):

### 1. Task-Type Following Collapse
**Problem (v0.2):** The model selected `concrete_example` across almost all tasks because the prompt formatting pipeline dropped the `task` and `instruction` fields, rendering tasks indistinguishable.
**Fix (v0.3):** 
- The input pipeline (`src/oloric/schemas/model_input.py`, `src/oloric/formatting.py`) was updated to embed the instruction into the system prompt.
- **Dataset Enhancement:** We introduced **category-specific student conversation turns**. Instead of a generic "I'm struggling to understand X", the student's prompt now implies the task. For example, in `simplification`, the student says, "The textbook explanation of X is way too complicated. Can you simplify it?" This provides strong semantic signal to the model even before the system instruction is parsed.

### 2. Cross-Domain Caloric Bleed
**Problem (v0.2):** Nutrition-domain examples (e.g., "500-calorie deficit") bled into unrelated domains (e.g., Accountancy) because the generator used centralized, domain-agnostic pools and Cartesian sampling for examples, analogies, and hints.
**Fix (v0.3):**
- Implemented `scripts/v03_concept_registry.py`, a rigid concept registry containing 60 distinct concepts across 6 domains (10 per domain).
- Every concept explicitly defines its own `concrete_examples`, `analogies`, `hints`, and `practice_problems`. 
- Cartesian sampling is entirely eliminated. A Mathematics concept (e.g., "Derivatives") only ever draws from math-specific examples and analogies.

### 3. Misconception Correction Incoherence
**Problem (v0.2):** The model correctly diagnosed misconceptions but generated generic, formulaic refutations ("shows that it provides tools") because the training targets used template placeholders instead of genuine content.
**Fix (v0.3):**
- The concept registry pairs explicit misconceptions with detailed, concept-specific refutations.
- Example: Rather than "This assumption is incorrect. It actually means...", the target response now explicitly refutes the misconception: "The statement 'GDP measures the total well-being of a country's citizens' is a common misconception. GDP only measures market output. It excludes unpaid household work...".

### 4. Document Grounding Disconnect
**Problem (v0.2):** The model ignored document context because `document_grounded` examples incorrectly targeted the `simple_explanation` strategy, teaching the model to ignore the context.
**Fix (v0.3):**
- `document_grounded` records now correctly target `strategy: "document_grounded"`.
- The target response explicitly quotes the `selected_text` from the `document_context` and synthesizes it with the explanation, creating a strong connective tissue between the context and the model's output.

## Quality Validation Gates
During generation, the script `scripts/generate_v03_dataset.py` enforced the following quality checks, all of which passed:
1. No template placeholders (`[placeholder]`, `TODO`, `FIXME`) remain in the dataset.
2. All IDs use the `v03_` prefix.
3. Every record contains an explicit `instruction`.
4. `document_grounded` records correctly target the `document_grounded` strategy.
5. Misconception records contain substantive refutations, verified by checking against the known v0.2 template strings.
6. Absolute separation of domains: Calorie markers are absent from non-Nutrition domains.
7. Deduplication: Confirmed that record IDs are unique and no cross-domain overlap exists.

## Next Steps
With the v0.3 dataset built and validated, it is ready for training. The fixed pipeline and concept-aware dataset structure should resolve the benchmark failures observed in v0.2.
