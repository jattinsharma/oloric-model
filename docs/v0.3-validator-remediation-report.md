# OLORIC v0.3 Validator Remediation Report

## Executive Summary

A root-cause classification audit was performed on the strict v0.3 content validator (`scripts/validate_dataset_content.py`) following its initial failure on `data/generated/oloric_v03_dataset.jsonl`. 

The initial run reported:
- **Placeholder occurrences:** 18
- **Affected records:** 16
- **Warnings:** 313
- **Result:** FAIL

Our audit revealed that:
1. **0 out of 18 errors are real unresolved placeholders.** All 18 reported errors are validator false positives triggered by legitimate mathematical and scientific notation.
2. **212 out of 313 warnings were real generator hygiene defects.** Specifically, `memory.candidate=False` was paired with populated memory fields across 17 generator functions because the generator lacked conditional gating on the memory proposal fields.
3. **101 out of 313 warnings were legitimate natural language pedagogical phrasing** (`hint 1`, `hint 2`, `hint 3`, `specific evidence`) that the validator flags for human review as non-fatal warnings.

Both the validator rules and the dataset generator were remediated at their source, followed by deterministic dataset regeneration, split materialization, and re-validation.

## 3. False-Positive Analysis

### 3.1 Chain Rule Function Composition: `[f(g(x))]` (14 occurrences)
- **Source:** Formula in `scripts/v03_concept_registry.py` under Mathematics -> Derivatives: `Chain rule: d/dx[f(g(x))] = f'(g(x))·g'(x)`.
- **Why Flagged:** The validator's bracket regex `r"\[[^\[\]\n]{1,80}\]"` matched `[f(g(x))]`.
- **Why False Positive:** In standard mathematical typography, brackets are used to delimit the argument of differential operators $d/dx[\cdot]$. `f(g(x))` is standard function composition, not a template slot.

### 3.2 Fundamental Theorem of Calculus Evaluation: `[3x²/2]` and `[x²]` (3 occurrences)
- **Source:** Numerical examples in `scripts/v03_concept_registry.py` under Mathematics -> Integrals:
  - $\int_1^4 3x\,dx = [3x^2/2]_1^4 = 24 - 1.5 = 22.5$
  - $\int_0^3 2x\,dx = [x^2]_0^3 = 9 - 0 = 9$
- **Why Flagged:** The bracket regex matched `[3x²/2]` and `[x²]`.
- **Why False Positive:** In integral calculus, bracket notation $[F(x)]_a^b$ or $[F(x)] \text{ from } a \text{ to } b$ denotes the antiderivative evaluated at upper and lower integration limits.

### 3.3 Relational Inequalities Spanning Sentences: `< 10 ... >` (1 occurrence)
- **Source:** Record `v03_nutrition_food_science_numerical_example_002` in target response:
  *"A meal with GL < 10 is low glycemic load, 10-20 is medium, >20 is high."*
- **Why Flagged:** The validator's angle bracket regex was `re.compile(r"<[^<>\n]{1,80}>")`. It matched from `<` in `GL < 10` through `>` in `>20 is high`.
- **Why False Positive:** The `<` and `>` characters are independent mathematical inequality symbols ("less than 10" and "greater than 20"). They do not form an enclosed angle-bracket placeholder.

## 4. Real Defect Analysis

### Memory Candidate & Field Population Incoherence (`MEMORY_FALSE_BUT_FILLED`)
- In `src/oloric/schemas/model_output.py`, `Memory` defines:
  ```python
  candidate: bool = Field(False, description="Whether this should be stored as a memory")
  title: Optional[str] = Field(None)
  content: Optional[str] = Field(None)
  anchor_concept: Optional[str] = Field(None)
  memory_type: Optional[str] = Field(None)
  confidence: float = Field(0.0)
  ```
- **The Defect:** When `candidate=False`, the tutor is explicitly *not* proposing a memory for storage. Populating `title`, `content`, `anchor_concept`, and a non-zero `confidence` is logically inconsistent and trains the model to generate phantom memory candidates that are flagged as inactive.
- In `create_diagnostic_questions` and `create_follow_up_questions`, the generator previously set `title=None, content=None, anchor_concept=None, memory_type=None, confidence=0.0`. However, in the other 17 functions, the generator evaluated `candidate: rng.random() > threshold` but hardcoded the strings into the dictionary, leaving them populated whenever `candidate=False`.
- **Impact:** 212 records out of 480 exhibited this defect.

14. `create_partial_understanding`
15. `create_understanding_confirmation`

17. `create_context_retention`

All 17 functions were refactored to construct memory through a unified helper:
```python
def _make_memory(
    candidate: bool,
    title: Optional[str] = None,
    content: Optional[str] = None,
    anchor_concept: Optional[str] = None,
    memory_type: Optional[str] = None,
    confidence: float = 0.0,
) -> Dict[str, Any]:
    if candidate:
        return {
            "candidate": True,
            "title": title,
            "content": content,
            "anchor_concept": anchor_concept,
            "memory_type": memory_type,
            "confidence": confidence,
        }
    return {
        "candidate": False,
        "title": None,
        "content": None,
        "anchor_concept": None,
        "memory_type": None,
        "confidence": 0.0,
    }
```

## 6. Exact Validator Changes Implemented

In `scripts/validate_dataset_content.py`:

```diff
 BRACKET = re.compile(r"\[[^\[\]\n]{1,80}\]")
-ANGLE = re.compile(r"<[^<>\n]{1,80}>")
+ANGLE = re.compile(r"<[a-zA-Z_][a-zA-Z0-9_\-\s]{0,60}>")
 GENERIC = re.compile(
     r"\bplaceholder\b|\bTODO\b|\bTBD\b|\bFIXME\b|\bLOREM\b"
     r"|to be filled|to be determined|fill in the blank|insert [^\n]{0,40} here",
     re.IGNORECASE,
 )

 ALLOWLIST = [
     re.compile(r"^\[H\u207a\]$"),            # [H+]
     re.compile(r"^\[OH\u207b\]$"),           # [OH-]
     re.compile(r"^\[e\u207b\]$"),            # [e-]
     re.compile(r"^\[H\u2083O\u207a\]$"),     # [H3O+]
     re.compile(r"^\[[A-Z][a-z]?[0-9]*[\u207a\u207b\u00b2\u00b3]{1,2}\]$"),  # [Na+], [Ca2+], ions
     re.compile(r"^\[\s*-?\d+(\.\d+)?(\s*,\s*-?\d+(\.\d+)?)*\s*\]$"),        # [0.4, 0.6], [1,2]
+    # Legitimate mathematical notation:
+    # 1. Composite function notation: [f(g(x))], [g(x)], [f(x)]
+    re.compile(r"^\[[a-zA-Z]\([a-zA-Z0-9_\(\)]+\)\]$"),
+    # 2. Definite integral evaluation brackets / single-variable algebraic terms: [3x²/2], [x²], [2x]
+    re.compile(r"^\[[-+]?\d*[a-zA-Z](\u00b2|\u00b3|\u2074|\u2075|\u2076|\u2077|\u2078|\u2079|\u2070|\^\d+)?(\s*/\s*\d+)?\]$"),
 ]
```

### Safety and Strictness Verification
- Actual placeholders (`[clear, concise definition]`, `[reason]`, `[example]`, `[hint 1]`, `[hint 2]`, `[question 1]`, `[everyday analogy]`) do **not** match the new regexes because they consist of multi-character English words, spaces without operators, or lack function parentheses.
- Angle-bracket placeholders (`<explanation>`, `<TODO>`, `<concept_name>`) continue to be strictly detected.
- Mathematical inequalities (`< 10`, `>20`) are no longer conflated with angle-bracket enclosures.
