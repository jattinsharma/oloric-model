## 2. How the corrected dataset was produced

`scripts/fix_seed_data_v02.py` drives the **improved generator's content-filled `create_*` functions** (all 20 categories) directly — the upstream files are imported, never modified:

- **Composition**: 4 examples/category × 20 categories × 6 domains = **480** (matches v0.1's exact balance; the improved generator's own assembly loop would have emitted ~2,814 examples, so it is bypassed deliberately).
- **Determinism**: `random.Random(42)`; every `random.*` call in the generators is seeded; helper picks are concept-indexed.
- **Defects patched at generation time** (upstream improved generator left as-is):
  1. `create_simplification`'s literal `[everyday analogy]` slot → replaced with concept-driven everyday comparisons per domain.
  2. `get_concept_explanation()` returned the domain's first formula regardless of concept (e.g. "GDP is defined by MPC = ΔC/ΔY") → replaced with a **per-concept explanation table** (~55 concepts, concept-correct definitions) with a safe fallback.
  3. `get_concept_example()`/reasons made concept-deterministic; per-concept importance reasons added for key concepts.
  4. `create_diagnostic_questions`' generic 4-question template was **verbatim-identical to 4 benchmark targets** (verified leakage) → replaced with 4 rotating, concept-specific, index-varied diagnostic variants probing definitional / orientation / confidence / application confusion modes.
  5. ID namespace: all v0.2 IDs prefixed `v02_` (the benchmark reuses the same `{domain}_{category}_NNN` scheme; unprefixed IDs collided on 3 IDs).
  6. Memory-shape hygiene enforced: `candidate=True` ⇒ title/content/anchor present; `candidate=False` ⇒ memory fields cleared and confidence 0.0 (v0.1 had 279 inconsistent records; see §4).

## 3. Placeholder validation (the new gate)

`scripts/validate_dataset_content.py` scans **every string field** recursively for: square-bracket slots `[...]` (with allowlist for chemistry `[H⁺]`-style ions and numeric intervals `[0.4, 0.6]`), angle placeholders `<...>`, markers (`placeholder`, `TODO`, `TBD`, `FIXME`, `LOREM`, "to be filled/determined", "insert … here"), and warns (non-fatal) on literal template phrasing and memory-shape inconsistencies.

**Gate results:**

| Dataset | Placeholder occurrences | Affected records | Result |
|---|---|---|---|
| **v0.1** (`enhanced_seed_data.jsonl`) | **2,725** | 456/480 | **FAIL** (2,725 errors) |
| **v0.2** (`oloric_v02_dataset.jsonl`) | **0** | 0/480 | **PASS** |

v0.1 top slots still present in it: `[reason]` ×205, `[explanation]` ×192, `[different concept]` ×144, `[correct explanation]` ×120, `[analogy]` ×72, `[description]` ×72, `[hint 1]`/`[hint 2]`/`[hint 3]` ×48 each. (Slightly below the root-cause audit's 2,765 raw-regex figure because the 36 chemistry `[H⁺]` allowlist hits are now correctly excluded — the gate allows legitimate notation.)

v0.2's 144 **warnings** (non-fatal) are all benign: 120 are the literal labels "Hint 1/2/3:" immediately followed by real content in `hint_based_teaching` records, 24 are the instruction phrase "using specific evidence from the document" in `document_grounded` — natural English, not slots. 0 memory-shape warnings remain (v0.1 had hundreds).

## 8. Known limitations (disclosed, not fixed in this phase)

1. **Content depth is still generator-grade**: filled content is factually correct but compact (single-sentence explanations, fixed example pools). The base model's own fluency exceeds these targets — the same effect seen in the benchmark (where targets sometimes scored below the baseline's free generations). Training on v0.2 should therefore be validated first on a small smoke run; the risk is style-narrowing, not placeholder collapse.
2. **Instruction-template overlap with benchmark** (16 strings) — see §5; inputs only, disclosed.
3. **`misconception_detection` targets** use "misconception ⇒ explanation" glue text ("This is incorrect because {explanation} shows that {reason}") which reads slightly awkwardly — harmless to training signal but worth polishing in v0.3.
4. The improved generator's `create_prerequisite_detection` adds a non-standard `missing_prerequisite` key inside `diagnosis`; it passes schema validation today but should be aligned with `OloricModelOutput` when the schema is next touched.
